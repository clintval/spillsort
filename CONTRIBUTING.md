# Developer Documentation

## Local Compilation

Install [uv](https://docs.astral.sh/uv/) and a [Rust toolchain](https://rustup.rs), then build the extension and install the development environment with:

```console
uv sync --locked
```

The extension is built with [maturin](https://www.maturin.rs), and `uv sync` rebuilds it whenever the Rust sources change.
The Rust crate builds without Python; the bindings are behind its `python` feature, which maturin turns on.

## Local Testing

To ensure all tests pass, run:

```console
uv run poe check-tests
cargo test
```

The Python tests check the sorter against `sorted()` with [Hypothesis](https://hypothesis.readthedocs.io), drawing new items on every run, except when `CI` is set, where they draw the same items each time.
The examples in the README are tested too: the Python ones by `pytest` and the Rust one by `cargo test`.

## Fuzzing

The [cargo-fuzz](https://rust-fuzz.github.io/book/cargo-fuzz.html) targets in `fuzz/` check that encoded keys order as Python orders the values, and that sorting arbitrary records with any memory and any number of open runs is a stable sort.
The [`fuzz.yml`](.github/workflows/fuzz.yml) workflow runs each for ten minutes every week.
To run one locally, install a nightly toolchain and `cargo install cargo-fuzz`, then run:

```console
cargo +nightly fuzz run key_order
```

## Local Linting and Formatting

To check the format, lint, and types of all the code, and run every test, run:

```console
uv run poe check-all
```

To fix what can be fixed automatically, run:

```console
uv run poe fix-all
```

## Releasing

Releases are published to PyPI and crates.io by the [`publish_spillsort.yml`](.github/workflows/publish_spillsort.yml) workflow with trusted publishing, so no API token is stored in GitHub.
crates.io trusts a workflow only for a crate that already exists, so publish the first version with `cargo publish` by hand before tagging it; the workflow skips any version that crates.io already has.

To release:

1. Bump the version in `Cargo.toml`, the only place it is set, since `pyproject.toml` reads it from there, run `cargo update --workspace` to update `Cargo.lock`, and merge a pull request titled `chore(release): bump to X.Y.Z` into `main`.
2. Tag the merge commit on `main` and push the tag:

   ```console
   git tag X.Y.Z
   git push origin X.Y.Z
   ```

3. The workflow checks that the tag matches the version, runs the tests, builds the sdist and wheels for every platform, checks that each wheel installs and imports, publishes to PyPI and crates.io, and creates a GitHub release with notes generated by git-cliff.
